# The gauntlet loop: what was judged, and how it ended

Every onboarding and app screen was captured with Playwright, paired blind with a real screen of a public open-source app (the *bar*, see `bar/manifest.json`: repo, commit and path for each), and judged by a fresh critic that never saw the code. A piece **wins** only when the critic picks ours *and* lists zero rule breaches on our side (the six rules in `docs/00-BUILD-PROMPT.md`, plus 44px targets, no truncation, no overlap). The loop ran six rounds per piece; after round 6 without a clean win a piece is **parked** for a human to call more rounds. That soft cap is a deliberate deviation from the gauntlet-loop skill, which says never to cap, so an unattended loop cannot spend everything on one piece.

**Result: 11 of 21 won, 10 parked.** In the final round the critic picked ours in every open piece; the parked ones each carry one to three residual flags, listed below verbatim so the next round starts from them.

## Residual flags on the parked pieces

These are the critic's own words from the last round. Three themes account for most of them: the header chip `Ta cote R 31,20` shown without a date beside it; controls the critic measured at 36–42px against the 44px floor; and two readings that are not defects in the code (a fixed tab bar overlapping the fold of a static screenshot, and identical published minimums across programmes read as placeholders when several universities publish the same 22,5 floor).

### S1 · App shell (nav, session chip, install guide)
*Gap named by the critic:* Top bar controls are undersized and over-stuffed: the bell circle and the "FR / EN" pill next to the "TA COTE R 31,20" chip measure roughly 36px tall — below the 44px floor and well below the stated 48px target — and four competing elements (logo, chip, bell, language toggle) leave the chip's figure floating with no source or date beside it. Enlarging those two controls to 48px and dropping the language toggle out of the shell would settle both the target rule and the top-bar hierarchy. ‖ bar's gap: The floating mini player sits on top of live list content instead of padding it: "Sprite Fright - Blender Open Movi…" is truncated mid-word and the bar covers the fourth row so only "136 views • 6 days ago" survives, half-occluded. Reserving bottom inset for the player would remove both the overlap and the clipped row; the four unlabeled header icons (flame, feed, TV, bookmark) are the next thing to fix, since only the underline says which is active. ‖ A's shell does the harder job well — labelled tabs with an unambiguous blue active state on "MA COTE", every figure stamped ("Confirmée par ton cégep, saisie par toi le 28 août 2026", "Vérifié le 25 août 2026 · ulaval.ca"), no "??" anywhere, and "Au-dessus du minimum" stays a factual comparison rather than an admission prediction. B is competent but its chrome is cruder: two stacked header rows of unlabelled icons (an eye and a "?" that explain nothing), a jarring red bar over a black list, and a mini player that eats the content beneath it. A loses points only on its top bar, where the bell and language toggle are visibly below the 44/48px floor and the chip's number travels without its source. (confidence 4/5)

- Tappable controls under 44px: the notification bell circle and the FR/EN toggle in the top bar read as roughly 36px tall, failing the 48px target rule
- Content sliced by the opaque tab bar with no scroll padding: "Cotes publiées 2024–2025 : 30,5–31,0" is cut through the middle of the glyphs by the bottom nav
- Figure without adjacent source/date: the top-bar chip "TA COTE R 31,20" repeats the score with no verification stamp (mitigated only because it is labelled as the student's own cote)

### S2 · Empty / loading / error set
*Gap named by the critic:* The empty-state card at the top is the least emphatic thing on the page: "Pas encore de cote R : les bourses qui en dépendent apparaîtront après ta première session..." is set in the same muted grey body weight as secondary metadata, and its CTA "Voir les 3 bourses ouvertes maintenant" is a low-contrast outline pill that merely jumps to the list already visible 100px below. Give that message a real headline weight (or an icon/left rule) and make the button do something the eye cannot already do — otherwise the screen's whole reason for existing reads as fine print. ‖ bar's gap: Screen A never shows the state under test at all: it is a tilted marketing mockup of a "Save to reading list" sheet, with the article body clipped mid-word at the right edge ("bound planetary systen", "The Solar System[a] is t", "Of the obje", "Sun directly, the largest"), and the only "empty-ish" affordance is a bare "Create new" row that names no consequence. Closing it would mean replacing the promo crop with an actual empty/loading/error screen whose text fits the viewport. ‖ B is the only screen that is a state at all: it names the missing cote R, explains when it arrives, and hands over a concrete next action, with amounts sitting beside their issuer, a deadline, a verification date and a source domain. A is an app-store promo tile — no skeleton, no error, no retry, no empty copy, and text amputated at the crop line — so the criterion is unmeetable there. B's real weaknesses are craft, not truth: the empty-state message is under-weighted relative to the list behind it, and the card stack runs under the tab bar without a safe-area gutter. (confidence 5/5)

## Calling more rounds

```
GAUNTLET_OUT=/tmp/gauntlet   # any writable dir
npx tsx scripts/gauntlet/capture.ts --piece=A1 --round=7      # ours, against a running `next dev --webpack -p 3000`
npx tsx scripts/gauntlet/pair.ts --piece=A1 --round=7         # random blind A/B assignment with the bar
# hand rounds/A1/r7/pair/{a,b}-phone.jpg to a fresh critic; save its verdict as verdicts-r7.json
npx tsx scripts/gauntlet/record-verdicts.ts --round=7 --file=verdicts-r7.json
npx tsx scripts/gauntlet/progress.ts                          # re-renders progress/index.html
```
